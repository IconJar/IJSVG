The new implementation permits output caching for detached vector feImage inputs
whose drawing values can be frozen. happy-orange.svg has no feImage, so a second
fixture exercises the changed path: detached-vector-image.svg plus an in-memory
rounded vector path with a solid orange fill, assigned by the benchmark to the
first feImage primitive. It is synthetic, not a replacement for the user's SVG.
Gradients and other feImage variants were not benchmarked.

Control uses the same binary with prepareImageSnapshots replaced by a no-op only
inside the standalone process (IJSVG_BENCH_DISABLE_IMAGE_SNAPSHOTS=1). This isolates
the new snapshot/cache behavior while retaining the previous nested-cache change.
It is not a separately rebuilt historical revision; other new bookkeeping remains.

Each process records its first draw, then medians of 15 fresh-instance and 15
repeated-instance draws. Parsing, fixture setup and destination allocation are
excluded. Fresh/repeated order alternates within each process. Two passes reverse
control/current order. Timings below show the range of the two process medians,
not confidence intervals. Process-first observations are recorded separately in
snapshot-timings.csv and include process-wide lazy initialization.

At 512 px, repeats are 18.9-20.3x faster in the paired observations. Fresh draws
are 32-38% slower in those same pairs, paying for the extra output-cache snapshot.
Fresh bitmap requests/snapshots increase from 2 to 3; repeated requests drop from
2 to 0. Fresh CI output conversions remain at 1; repeated conversions drop 1 to 0.
At 512 px fresh requested bitmap bytes increase 2,097,152 -> 3,145,728; repeated
requests drop 2,097,152 -> 0. These are cumulative requested bytes, not peak memory.

Correctness observations
All captured first-render and repeated-render pixels are byte-identical between
control/current for both fixtures at 256, 512 and 1024 px in both passes. The
fixtures produced nonempty images. See snapshot-pixels.csv for comparisons and
SHA256 hashes. This narrow benchmark does not replace the correctness suites.

Artifacts
snapshot-timings.csv: all timing observations, including process-first draws.
snapshot-allocations.csv: fresh/repeated counters from separate profiling draws.
snapshot-pixels.csv: first/repeated output comparison results.
Allocation counters cover explicit bitmap requests and snapshots; conversion
counters cover CIContext createCGImage:fromRect:format:colorSpace:. They exclude
private GPU allocations and do not capture every internal conversion.

Reproduce from IJSVGExample, supplying Xcode's built products directory:
sh Benchmarks/run-sticker.sh PRODUCTS Benchmarks/StickerResults/happy-orange.svg OUTPUT
IJSVG_BENCH_VECTOR_IMAGE=1 sh Benchmarks/run-sticker.sh PRODUCTS \
  Benchmarks/StickerResults/detached-vector-image.svg OUTPUT
Prefix either command with IJSVG_BENCH_DISABLE_IMAGE_SNAPSHOTS=1 for the control.
Use separate output directories for each variant/pass and allow Metal access.
